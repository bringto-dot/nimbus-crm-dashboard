CRM-интерфейс, в котором основной акцент сделан на качестве UI, реалистичных
пользовательских сценариях и аккуратной организации frontend-части.

Nimbus объединяет основные рабочие процессы небольшой CRM в одном
интерфейсе: обзор показателей, работу с клиентами, воронку сделок и
управление задачами. Приложение работает полностью в браузере на
mock-данных, поэтому все основные сценарии доступны в Live Demo без
отдельного backend.

## Обзор

Приложение построено вокруг нескольких связанных CRM-сценариев, а не только
одного dashboard-экрана.

Dashboard показывает ключевые показатели, динамику выручки, этапы сделок и
последние сделки.

Раздел клиентов позволяет искать и сортировать записи, фильтровать их по
статусу, создавать и редактировать клиентов, выполнять валидацию форм и
удалять записи с подтверждением.

Раздел сделок построен в виде Kanban-воронки из пяти этапов. Сделки можно
перемещать между колонками с помощью drag-and-drop.

Раздел задач связывает задачи с клиентами и объединяет сроки, приоритеты и
статус выполнения в одном рабочем сценарии.

## Интерфейс

### Dashboard

Главный экран объединяет KPI-карточки, график выручки, распределение сделок
по этапам и таблицу последних сделок.

Информация собрана так, чтобы основные показатели оставались перед глазами
и не превращались в набор разрозненных виджетов.

### Воронка сделок

Раздел Deals построен вокруг пяти колонок Kanban:

`New → In Progress → Negotiation → Won / Lost`

Перемещение работает через pointer и touch-ввод, а для управления с
клавиатуры подключены отдельные keyboard-сенсоры.

![Kanban-доска сделок](docs/screenshots/04-deals-kanban.png)

### Клиенты и задачи

С клиентами можно работать через поиск, фильтрацию, сортировку, создание,
редактирование и удаление. При удалении клиента связанные с ним сделки и
задачи также удаляются из состояния приложения.

Задачи представлены в виде компактного checklist-интерфейса со связью с
клиентом, сроками, приоритетами и фильтрацией открытых и выполненных задач.

## Дизайн и адаптивность

Интерфейс поддерживает светлую и темную темы, а выбранная тема сохраняется
между сессиями.

Все основные части приложения доступны на русском и английском языках.
Даты и денежные значения форматируются в соответствии с активной локалью.

На небольших экранах боковая панель превращается в мобильное выдвижное
меню. В таблицах второстепенные колонки скрываются вместо появления
горизонтального переполнения, а Kanban сохраняет доступ ко всем колонкам
через горизонтальную прокрутку.

Адаптивное поведение проверено на разрешениях 375px и 1440px.

## Организация frontend

Код разделен по предметным областям, поэтому основная логика не
сосредоточена в одном большом dashboard-компоненте.

```text
src/
├── components/
│   ├── ui/
│   ├── common/
│   ├── layout/
│   ├── dashboard/
│   ├── clients/
│   ├── deals/
│   └── tasks/
├── data/
├── hooks/
├── i18n/
├── lib/
├── pages/
├── store/
└── types/
```

Основные доменные модели приложения: `Client`, `Deal` и `Task`. Изменения
состояния проходят через именованные actions Zustand, а производные
значения, включая KPI и группировку сделок по этапам, вынесены в
selectors.

Так UI-компоненты отвечают за отображение и взаимодействие, а состояние
приложения и производные данные остаются разделенными.

## Детали реализации

### Типизированная модель данных

TypeScript работает со строгими проверками, включая контроль
неиспользуемых переменных и неявных возвращаемых значений. Доменные типы
используются в store, selectors, формах и UI-компонентах.

### Drag-and-drop

Kanban реализован через `@dnd-kit` с pointer, touch и keyboard sensors. Для
touch-взаимодействия добавлена задержка активации, чтобы обычная прокрутка
страницы не воспринималась как начало перетаскивания.

### Локализация

Английский словарь определяет набор ключей переводов приложения, а русская
версия обязана реализовать ту же структуру. Поэтому отсутствие перевода
становится проблемой типов, а не незаметной пустой строкой в интерфейсе.

### Сохранение темы

Настройки темы и языка сохраняются через Zustand. Класс темы применяется
еще до монтирования React, благодаря чему при первоначальной загрузке не
возникает заметного переключения темы.

## Деплой

Проект размещен на GitHub Pages.

Каждый push в `main` запускает сборку приложения и публикует директорию
`dist` через GitHub Actions. Для production используется `HashRouter`, что
позволяет корректно работать с маршрутами на GitHub Pages без серверных
rewrite-правил.

## Границы проекта

Nimbus CRM использует mock-данные и browser storage вместо production
backend. Цель проекта — показать интерфейс, работу состояния приложения,
интерактивные сценарии, адаптивность и организацию frontend в полностью
самостоятельном проекте.

## Итог

Nimbus CRM показывает, как dashboard можно построить как цельный
продуктовый интерфейс, а не как набор отдельных экранов: представление
данных, формы, фильтры, Kanban-взаимодействия, управление состоянием,
локализация, темы и адаптивная верстка работают вместе в одном приложении.
